# Правила для агентів

Цей файл читають агенти (Claude Code, Codex, Cursor та інші) перед роботою з репозиторієм.
Що робити далі — в [ROADMAP.md](ROADMAP.md); як влаштовано код — у [README.md](README.md).

## Проєкт коротко

Glassgram — десктопний клієнт Telegram на Rust: `eframe`/`egui` (рендер `wgpu`), MTProto через
`grammers` (шар API 230). Ліцензія GPL-3.0-or-later. Інтерфейс — копія структури Telegram Desktop
з шаром «рідкого скла» поверх.

```sh
cargo build --release
cargo test --release
cargo run --release -- --demo   # вигадані чати без мережі
cargo run --release             # справжній акаунт (сесія в ~/.local/share/glassgram)
```

Перед завершенням роботи збірка має бути **без попереджень**, тести — зелені.

## Архітектура

- **`backend.rs`** — окремий потік з tokio. UI шле `Cmd`, бекенд відповідає `Ev` через канали.
  UI ніколи не чекає на мережу.
- **`app.rs`** — увесь стан і малювання. Події обробляє `push_event`, дії користувача — `apply`.
- **`demo.rs`** — відповідає на ті самі `Cmd` синхронно, без мережі. Код має витримувати те, що
  відповідь (`Ev`) прийде вже всередині `send()`.
- Медіа: `player.rs` (звук через `ffplay`), `video.rs` (кадри з `ffmpeg` у текстуру),
  `recorder.rs` і `camera.rs` (запис), `export.rs`, `accounts.rs`, `settings.rs`, `lock.rs`, `i18n.rs`.
- Скло: `glass.rs` (кольори, панелі, кнопки, поля), `blur.rs` + `glass.wgsl` (GPU-розмиття), `icons.rs`.

### Як додати функцію

1. Варіант `Cmd` (із doc-коментарем) і обробник у `Worker::handle`.
2. Варіант `Ev` для результату. Довгі операції — у `tokio::spawn`, щоб не блокувати інші команди.
3. Обробка `Ev` у `App::push_event`, стан — поля `App` з коментарем.
4. Інтерфейс — окремий метод `*_view` або функція, кольори й скло — лише через `glass::*`.
5. **Обов'язково** — відповідь у `demo.rs` і демо-дані, щоб функцію було видно в `--demo`.
6. Оновити `ROADMAP.md` (позначка ✅/🟡) і `README.md`, якщо змінилось керування чи структура.

## Стиль коду

- Коментарі й doc-коментарі — українською, коротко: **чому**, а не що.
- Читайте сусідній код і пишіть так само: та сама щільність коментарів, імена, ідіоми.
- Без `unwrap()` на даних з мережі й диска; помилки — рядком у `Ev::Error`.
- Нові залежності — лише чистий Rust, що збирається на Linux, Windows і macOS без системних
  dev-бібліотек. Перш ніж додати крейт, перевірте, чи нема готового в `Cargo.lock`.

### Тексти інтерфейсу

Кожен рядок інтерфейсу — двома мовами поруч, через макроси з `i18n.rs`:

```rust
l!("Скасувати", "Cancel")                    // &'static str
lf!("Голосів: {n}", "Votes: {n}")             // як format!, аргументи перевіряє компілятор
```

Рядок без перекладу — помилка. Вміст із сервера (назви чатів, тексти) не перекладаємо.

### Кросплатформність

Новий код має працювати на Linux, Windows і macOS:
- файли й посилання відкривати через `open::that_detached`, а не `xdg-open`;
- теки брати з `dirs` (`download_dir`, `data_dir`), а не з XDG-змінних;
- мову системи — з `sys_locale`; права на файли — `backend::make_private`;
- якщо без ОС не обійтися — `#[cfg(target_os = …)]` для **кожної** платформи, а не лише Linux.

## Дизайн-код

### Звідки береться інтерфейс

1. **Структура й поведінка — з Telegram Desktop.** Розташування екранів, порядок пунктів меню,
   розділи налаштувань, гарячі клавіші, тексти — як в офіційному клієнті. Не вигадувати свої
   схеми, якщо в Telegram уже є відповідь.
2. **Матеріали й рух — за принципами Apple** (Human Interface Guidelines, Liquid Glass 2025).
   Беремо принципи, не ресурси: SF Symbols і шрифти Apple ліцензією дозволені лише на платформах
   Apple, тому іконки малюємо самі в `icons.rs`.

### Де скло, а де ні

Скло — це **шар керування, що плаває над вмістом**. Не вміст.

| Скло доречне | Скла не треба |
|---|---|
| шапка чату, поле вводу, вкладки папок, бічні панелі | текст повідомлень і довгі списки |
| спливні меню, підказки, діалоги, плеєр, тости | фото, відео, мапи — вони самі є вмістом |
| бульбашки — легке тонування (`Glass::tinted`) | скло поверх скла (не більше одного шару) |

- Щільність і тонування — через готові пресети: `Glass::panel`, `Glass::tinted(..).frosted(..)`.
  Акцентний тон (`ACCENT`) — лише для головної дії на екрані.
- Текст на склі має читатися за будь-якого фону: якщо фон строкатий (медіа), під текст іде темний
  чип і колір `glass::ON_DARK`.
- Поважати «Зменшити прозорість» і «Підвищити контраст» — на них скло стає щільним.

### Токени

- **Кольори — лише функціями**: `ink()`, `ink_dim()`, `chrome()`, `veil(a)`, `ACCENT`,
  `ON_DARK`, `bubble_in()`, `link(out)`. Жодних `Color32::from_rgb` для тексту чи фону в нових
  місцях — інакше зламається одна з тем.
- **Відступи** — сітка 4 pt: 4, 8, 12, 16, 24. Поля панелей — 14–18 pt.
- **Радіуси** концентричні: внутрішній = зовнішній − відступ. Капсули — радіус = висота / 2.
  Панелі — 24–28, бульбашки — 18, кнопки-кола — половина сторони.
- **Шрифт** — Ubuntu (вбудований). Шкала: 11 (мітки часу), 12.5 (підписи), 13.5–14.5 (списки),
  15 (текст повідомлень), 17 (заголовки вікон), 24 (заголовок розділу).
- **Цілі для кліку** — не менше 32 pt, кнопки-іконки — 36–50 pt.
- **Рух** — 150–350 мс, пружинні криві; плавно, але без затримки реакції на клік.
- **Іконки** — векторні на сітці 24×24, лінія ≈1.9 pt, заокруглені кінці (`icons.rs`).

### Перевірка вигляду

Кожну зміну інтерфейсу перевіряйте **в обох темах і обох мовах**. Скриншотів системними
утилітами немає (Wayland), тож використовуйте тимчасовий хук в кінці `App::ui`:
`egui::ViewportCommand::Screenshot` → `image::save_buffer`. Позначайте його `// TMP-SHOT`
і **видаляйте** перед завершенням (перевірка: `grep -c TMP src/app.rs` дає 0).

## Перевірка на справжньому акаунті

- Демо доводить лише вигляд. Протокол перевіряйте на справжньому акаунті тимчасовим прогоном
  без вікна (`src/probe.rs` + прапорець `--probe`), який шле `Cmd` і звіряє `Ev`. Після перевірки — видалити.
- У вивід — **лише кількості й типи**, без назв чатів, імен і текстів.
- Без явного дозволу власника — **тільки читання**. Надсилати можна лише в чати, які власник
  назвав сам; кожне тестове повідомлення позначати `[тест Glassgram]`.
- Ніколи без прямого дозволу: завершувати сеанси, змінювати приватність, вступати чи виходити
  з чатів, видаляти чуже, платити Stars.

## Безпека

- Файли сесії, облікових даних і налаштувань — лише для власника (`make_private`).
- Не логувати номери, коди, паролі, ключі сесії, тексти повідомлень.
- Тимчасові файли (запис, експорт) — у `std::env::temp_dir()`, видаляти після надсилання.
- Гаманець, платежі й секретні чати — лише з окремим оглядом безпеки перед злиттям.
